`@saykit/react` is split across three entry points:

```ts
import { Say } from '@saykit/react'; // shared (server + client)
import { SayProvider, useSay } from '@saykit/react/client'; // client only
import { setSay, getSay, unstable_createWithSay } from '@saykit/react/server'; // server only
```

The default `@saykit/react` import uses the `react-server` export condition to swap between the server and client implementations of `<Say>` automatically.

## `@saykit/react`

### `<Say>`

The primary translation component. Author content as children.

```tsx
<Say>Hello, {name}!</Say>
```

## `@saykit/react/client`

### `<SayProvider>`

Wraps a client tree with a locale and message catalogue. Required before any client-side use of `<Say>` or `useSay()`.

It takes the view's data rather than the view itself. A view is a callable closure, so it cannot cross the server/client boundary; its locale and messages are plain data and can. The provider builds a view from them on the client and memoises it, so `useSay()` returns the same value until the locale or messages change.

```tsx
<SayProvider locale={locale} messages={messages}>
  {children}
</SayProvider>
```

Props:

<TypeTable
  type={{
    locale: {
      description: 'The active locale string.',
      type: 'string',
      required: true,
    },
    messages: {
      description: 'The message catalogue for the locale.',
      type: 'View.Messages',
      required: true,
    },
    children: {
      description: 'The tree to provide a view to.',
      type: 'ReactNode',
    },
  }}
/>

Internally builds a `View` over the locale and messages, with `createView`.

### `useSay()`

Returns the `View` from the nearest `<SayProvider>`. Throws if no provider is in the tree.

```ts
function fn() {
  const say = useSay();
  return say`Hello, ${name}!`;
}
```

## `@saykit/react/server`

### `setSay(say)`

Register a `View` for the current request. Must be called before any server component renders `<Say>`.

```ts
setSay(catalogue.locale(locale));
```

A view is immutable, so it is stored exactly as it arrives, with nothing to clone or freeze against a concurrent request.

### `getSay()`

Returns the registered `View` for the current request. Throws if none has been registered.

```ts
const say = getSay();
```

The server equivalent of `useSay()`.

### `unstable_createWithSay(catalogue)`

Returns a `withSay()` higher-order component factory bound to a `Catalogue`.

```ts
const withSay = unstable_createWithSay(catalogue);
```

`withSay(Component, getLocale)`:

<TypeTable
  type={{
    Component: {
      description:

      required: true,

The wrapper runs `match()`, `load()`, `locale()`, and `setSay()` before rendering. Useful in App Router layouts and pages where the URL param dictates the locale.

## Types

### `PropsWithSay<P>`

```ts
type PropsWithSay<P = unknown> = P & { locale: string; messages: View.Messages };
```

The shape `withSay`-wrapped components receive.
